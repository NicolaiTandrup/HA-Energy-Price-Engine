# ADR-001: independent native price producer, API v1 and durable ledger

Status: accepted for developer preview, 2026-10-24. Tracks issues #1–#5.

## Decision

Use native domain `ha_energy_price_engine`, one independent HA config entry per
stable site ID. Each site chooses its official Nord Pool entry, price area, IANA
zone, DSO mode, explicit VAT and dated component rules. No charger or vehicle
code belongs here. EV Charge Manager, HVAC and batteries are read-only consumers.

Port the tested pricing stack from EV Manager PR #11/#12; see PROVENANCE.md.
Retain its pipeline: Fetch → Normalize/Validate → Calculate → Persist → Lookup.
Official Nord Pool's read service is requested in DKK and returns ex-VAT DKK/MWh;
normalize once by 0.001. Radius is accepted only with exact GLN/product/charge type,
PT1H, complete effective coverage and verified ex-VAT convention. VATClass is not
proof of VAT inclusion. API reads neither fetch nor calculate.

## Persistence and settlement

HA Store v1 uses integration/entry/site-specific keys. HA's atomic file replacement
commits each complete requested day before its immutable in-memory index changes.
Concurrent writes serialize. A failed write leaves prior data authoritative.
Rejected partial publications cannot be mixed into the last verified table.

UTC quarter hours are canonical. Calendar-day bounds use local civil dates;
Denmark has 92/96/100 slots across DST. Already-started stored intervals retain
amounts and provenance. Missing historical rows may be backfilled with verified
inputs; this is not retroactive correction of settled records. Future corrections
have durable old/new row audit entries. Configuration changes have a separate
old/new configuration audit. Normal reads never mutate either.

Unlike the upstream's 365-day default, this producer retains history permanently.
The first preview uses indexed in-memory lookup and atomic JSON snapshots per site,
with bisect range queries. This is HA-compatible on Raspberry Pi but snapshots and
correction audit grow with history. A measured SQLite migration with schema tests
is a follow-up before claiming large multi-year scale; no hidden pruning occurs.
Schema version is independent of API and integration versions.

## Rates and overrides

All marginal amounts normalize explicitly to DKK/kWh. Each component declares VAT
inclusion and its own VAT fraction, source, verified date and half-open local date
period. Subscriptions are separately stored as DKK/month, excluded from slot totals.
Locked manual components outrank automatic baselines. Equal-priority overlaps are
rejected. Missing DSO/supplier/TSO/tax coverage fails closed, never defaults to zero.

National baselines are bounded documented schedules, not live legislation discovery:
2026 TSO net/system, 2026–2027 uniform electricity tax. No 2028 rule is inferred.
The EWII household 0.030 DKK/kWh ex-VAT example is limited to June–September 2026,
never globally installed or applied to another site. Unknown later contracts need
new explicit periods. Heating eligibility never invents a discount rate.

## Refresh and publishing

Copenhagen clocks: unconditional 13:05 next-day check; conditional 13:20, 13:40
and 23:59 checks; unconditional 00:01 newly started-day check. Startup reconciles
current and next site-local dates. Only changed verified inputs or missing rows
recompose/persist prices. Verification timestamps alone are not price changes.
Native source notifications are coalesced with bounded service-attempt backoff.
API v1 emits events only after durable commit and only for changed future final
prices. A quarter-hour sensor tick only reads the ledger.

## Compatibility, review and release

Public API v1 is documented in API.md. Consumers feature-detect version/discovery,
check status and coverage and back off if unloaded, incomplete, stale or errored.
They own conservative behavior; missing price is never free electricity.

Developer preview only (`0.1.0-dev.1`), draft PRs, mocked services, CI including
hassfest and HACS metadata. No stable release, merge, production cutover or live
Home Assistant/Node-RED/charging changes without owner approval. API stability is
reviewable now; hardware acceptance and HACS catalog inclusion are separate work.
