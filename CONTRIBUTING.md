Repeat producer and unchanged consumer/runtime gates with requirements-ha-current.lock.
Prepare clean packages, install both ZIP layouts outside this repository, run actual
pinned HACS workflows and test the real native frontend before release. Never use
production HA or real charging equipment for these tests. A cloud SQLite benchmark
does not establish Raspberry Pi performance. Publication requires exact-source
successful CI, immutable tag and independently verified packages/checksums.


## Dashboard browser regression tests

Runtime card code has no npm dependency. Node24 and locked Playwright1.64.1 are
only development/CI tools. The browser fixtures are generated by the real HA
producer tests, not duplicated tariff calculations:

```sh
PE_FRONTEND_FIXTURES=/tmp/pe-dashboard-fixtures .venv/bin/pytest tests/test_beta8_dashboard.py -W error::ResourceWarning
npm ci --ignore-scripts --prefix tests/frontend
cd tests/frontend
npx playwright install --with-deps chromium
cd ../..
PE_FRONTEND_FIXTURES=/tmp/pe-dashboard-fixtures node --test tests/frontend/dashboard.test.mjs
```

With an existing system Chromium, set `PE_CHROMIUM=/usr/bin/chromium` for the last
command instead of installing a browser. All15 cases must pass; errors are not
ignored. Native HA desktop/mobile acceptance is separate: use an isolated copy and
recorded/synthetic provider boundaries, never an owner's live HA or controls. Keep
screenshots, authentication, test profiles and transient browser output outside
tracked source. See the permanent development handoff for release evidence.
